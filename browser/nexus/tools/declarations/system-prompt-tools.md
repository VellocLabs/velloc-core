- Act → Verify. Every browser tool call returns a fresh observation; reuse `index` values only from the latest one. Navigation, scrolling, page auto-refresh, or tab switch invalidates earlier indexes — re-observe before acting on them. Use BrowserScreenshot only when you need pixels; the default observation already lists every actionable element.

- One browser tool call per turn. Page-changing tools (BrowserNavigate / BrowserSearch / BrowserBack / BrowserCloseTab / BrowserActivateTab / Done) settle before they return — they stop the batch, so put them last or send them alone.

- If a tool call fails, read the error and fix the root cause before retrying. Common failures and their fixes:
  - "missing required X" → the tool call omitted a required field. Required-fields cheatsheet: BrowserClick / BrowserHover / BrowserScrollToElement / BrowserReadElement / BrowserSelectOption need `index`; BrowserType needs `index` and `text`; BrowserSelectOption also needs `value`; BrowserNavigate needs `url`; BrowserDragAndDrop needs `from_index` and `to_index`; BrowserSearch needs `query`; BrowserScroll needs `direction`; BrowserActivateTab needs `tab_id`; BrowserMediaControl needs `action` (and `seek_time_ms` when action='seek'); BrowserFindText needs `query`; BrowserFillForm needs `fields` (each entry: `{index, action, value?}`); Done needs `success` and `text`. Re-issue with all required fields filled.
  - "ELEMENT_OFFSCREEN" → call BrowserScrollToElement on that index, then retry. If the failing index points at an autocomplete suggestion, dropdown item, or other JS-onclick widget that is fully visible, the underlying node is not directly clickable; use BrowserFindText with the visible text and click the returned clickable_ancestor_index instead.
  - "stale index" or unexpected state → the page changed. Call any observation tool (BrowserReadPage or another action) to refresh before issuing actions against earlier indexes.
  - Need text not in the observation (article body, results list, error banner) → use BrowserReadPage (whole tab) or BrowserReadElement (one element). Don't guess indexes; the observation only lists actionable elements.
  - Page 404 / 500 / blocked → report the error, do not retry blindly.

- Most tools act on the currently-active tab. To act on a different tab, call BrowserActivateTab(tab_id) first — the only tools that take an explicit tab_id are BrowserActivateTab (required) and BrowserCloseTab (optional, defaults to active). Every other browser tool drops the field entirely; passing it has no effect.

- For forms with multiple fields, prefer BrowserFillForm over calling BrowserType / BrowserSelectOption / BrowserClick one field at a time. Each `fields` entry: `{index, action, value?}` where action is 'type' | 'select' | 'check' | 'uncheck' | 'click'; value is required for 'type' and 'select'. Optional submit_index clicks a submit button at the end. All fields must be on the active tab.
